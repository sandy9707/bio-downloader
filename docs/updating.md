# 更新与恢复

Windows 旧版本存在“下载补丁后退出，但没有替换程序”的问题。首次升级到修复版请使用完整安装包，安装到原目录；不要删除用户数据目录。便携 EXE 和无写入权限的安装目录继续使用完整安装包。

修复版 Windows / macOS 的补丁更新会：

1. 从官方清单取得 SHA256 和 Ed25519 签名，通过校验后暂存到安装目录。
2. 启动独立更新程序，确认它已准备好后，旧客户端才退出。
3. 等待旧进程退出，备份旧 `app.asar`，再替换并重新校验。
4. 启动同一安装位置的程序，由新窗口确认实际运行版本。替换或启动进程失败时尝试恢复旧版；不会把“已下载”显示成“已更新成功”。

更新期间请先结束下载和校验任务。更新结果位于用户数据目录的 `updates/`，旧程序备份在安装目录的 `resources/.biodl-update-*/previous.asar`。这些是程序备份，不是下载任务和账号数据备份。系统强制断电、磁盘硬件故障等仍可能需要人工恢复，不应仅凭进度条判断更新成功。

macOS 安装在只读 DMG 或没有写权限的目录时，请先将应用复制到“应用程序”，或使用完整 DMG 更新。

Linux 使用完整压缩包更新，不替换正在运行的 Node runtime。更新前从官方清单核对包摘要和版本，分阶段备份、替换程序文件；正常的替换错误会回退。`~/.bio-downloader/` 下的默认配置和任务历史、下载文件及程序目录中其他用户文件保留。备份在程序目录 `.biodl-update-*/previous/`。

```bash
./biodl update --check            # 只检查当前通道
./biodl update --preview --check  # 只检查预览版
./biodl update                   # 按当前通道安装
./biodl update --preview         # 明确选择预览版
```

命令行更新前请先停止同一程序目录运行的 Web 服务。Web 页发起更新后旧服务会退出；“程序文件已更新”不代表后台服务已重新启动。按照原来的启动方式重新运行服务：

```bash
nohup ./biodl start </dev/null > biodl.log 2>&1 &
disown
```

使用 PM2 / systemd 的用户通过原进程管理器重启，避免重复启动。重新打开网页或运行 `./biodl --version` 确认实际版本。
