# Axel 生物数据传输保护

## 已复现的缺口

内置 Axel 2.17.14 的 HTTP 传输在 `conn_exec` 中接受 2xx，未严格匹配每次请求的 Content-Range。故障服务对非零偏移返回文件开头的数据后，实际内置 Axel 仍退出 0，大小正确、删除 `.st`，但文件内容不同。测试是人工故障复现，不能据此断言某位客户遇到了同一故障。

参考上游源码：[conn.c](https://github.com/axel-download-accelerator/axel/blob/v2.17.14/src/conn.c#L307-L318)、[axel.c](https://github.com/axel-download-accelerator/axel/blob/v2.17.14/src/axel.c#L672-L703)，以及 [HTTP Range 语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)。

## 实现与范围

保留 Axel 的并发调度、写盘、原生暂停/恢复与 `.st` 续传，不替换 C 内核。`src/main/bio-transfer-guard.js` 在本机环回地址建立仅服务单个任务随机路径的保护层。它请求固定源文件；不接收任意 URL，不作为通用代理。

自动识别以下无认证、无查询参数的 HTTP(S) 静态地址，并升级至 HTTPS：

- `ftp.sra.ebi.ac.uk/vol1/fastq/`、`/vol1/srr/`、`/vol1/err/`、`/vol1/drr/`
- `ftp.ncbi.nlm.nih.gov`、`sra-download.ncbi.nlm.nih.gov`
- `sra-pub-run-odp.s3.amazonaws.com`

EBI 编号与上述域名的直链使用相同保护。普通网站、FTP/SFTP 插件、浏览器会话下载、云下载不自动切换此链路。Mihomo 开启时，保护层的所有上游请求仍经同一代理；禁止直接回退。只有 Axel 到本机环回地址这一跳不走代理。

每个上游分段在转发数据前验证：HTTP 206、Content-Range 起止位置与总大小、Content-Length（若存在）、内容编码、ETag/Last-Modified。对内容超长、提前结束和不同连接在抽样位置返回不同内容也报错。明确异常时停止传输，保留文件和断点，禁止转入清空文件重下的兜底流程。

## 快速检查与能力边界

默认不计算整文件 MD5。把最多 32 个 4 KiB 窗口分布在整个文件，包括首尾：新下载从传输流收集窗口指纹，再与磁盘小块比较；窗口跨连接边界时补取对应的小 Range。已有同名文件重新从源站取样后比较，避免仅凭同名同大小跳过。续传时检查已完成区域和续传边界的小块，不把尚未下载的位置当作损坏。

一次完整抽样本地最多读取 128 KiB；续传边界检查可能额外读取一些小块。这不是完整性证明：未抽中的损坏可能漏过，无可靠源版本标识时也无法完全排除源文件在下载过程中改变。界面、结果与日志都明确标记抽样，并记录 `fullContentVerified: false`。参考 MD5 仍为手动开启的独立全文校验，不假称抽样等同于官方 MD5 或 gzip CRC。

已有文件明确 MD5 不一致时，保留文件但不作为成功跳过。新下载的 MD5 差异仍提示人工核对，不自动归因于文件或参考信息，不自动删除重下。记录过差异的受保护文件在关闭 MD5 后也不能仅凭大小重新判成成功跳过。

## 断点与持久化

同目录 `.biodl.json` 保存源 URL 的 SHA256（不保存完整 URL）、源大小、版本标识、抽样指纹、检查结果与最近有效的 Axel 断点快照。原子替换避免写一半覆盖有效记录。

检查 `.st` 的字段长度、范围边界、未完成区间重叠与总字节计数；兼容当前 uint16 连接数及旧 int 格式。捕获有效快照后先同步对应数据，再原子保存备份；原 `.st` 损坏或丢失时，仅恢复经过 SHA256 与结构验证的备份。旧任务没有有效断点/备份时保留原文件并提示，不凭文件长度推断多线程写入进度。源版本变化时停止续传，避免新旧数据混拼。

暂停仍挂起原 Axel 进程。暂停引起上游连接超时，只关闭该连接，让 Axel 恢复后重新请求其当前偏移。同一进程内禁止两个受保护任务同时写同一目标文件。用户明确选择“删除记录和文件”时同时清理 `.biodl.json`。

## 回归

`npm test` 包含真实内置 Axel + localhost 故障服务：错误范围、忽略 Range、变化的 ETag、内容编码、截断、抽样差异、断点结构/原子备份恢复、仅补未完成部分、代理失败不直连、已有文件检查、原生暂停恢复取消和消费上报次数。另保留原有传输持久化、MD5 政策与平台进程控制测试。


### 2.0.45 下载失败修复与发布验证

- 修复三次 Axel 重试后备用函数及代理配置越过作用域，报 `downloadFileWithNodeStream is not defined` 的问题。
- 仅对没有已有数据或断点的 HTTP(S) 任务启用备用下载；已有文件和 `.st` 保留给 Axel 续传。备用流支持暂停、恢复、取消，异常时关闭读写流；开启代理后不再自动改为直连。
- ENA 的 `ftp.sra.ebi.ac.uk/vol1/fastq/…` 等公开静态归档使用 [官方说明](https://www.ebi.ac.uk/ena/browser/downloading-data) 的 HTTP 地址；不再强制改成 HTTPS。这一规范化只适用于已识别的无凭据、无查询参数的公开 EBI 归档地址。NCBI 的 HTTPS 规则保持不变。
- 短暂的分段 5xx/网络错误按分段有限重试，不能由多个并发线程共同耗尽一个全任务三次计数；错误 Content-Range、源版本变化仍立即停止并保留文件。
- Windows/macOS 发布检查必须通过真实 EBI 文件的完整下载，随后由测试独立计算全文件 MD5 对比 ENA 参考值。用户默认仍是快速检查，完整 MD5 仍为可选。
