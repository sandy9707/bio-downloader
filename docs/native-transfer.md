# BioDownloader 独立下载内核候选版

状态：独立原型，位于 `src/experimental/native-transfer`。生产客户端 2.1.2 的下载器选择、默认引擎、旧断点、云下载和计费均不接入此模块。该原型可通过命令行实际下载，尚不作为正式版默认引擎。

## 设计依据

参考 [aria2 的分块存储](https://github.com/aria2/aria2/blob/master/src/DefaultPieceStorage.cc)、[事件调度](https://github.com/aria2/aria2/blob/master/src/DownloadEngine.cc)、[控制文件和续传选项](https://aria2.github.io/manual/en/html/aria2c.html) 及 [Axel 的多连接设计](https://github.com/axel-download-accelerator/axel)。没有复制这两个 GPL 项目的源码；实现依据 HTTP 协议和本项目的故障案例独立编写。新增文件锁依赖 proper-lockfile 4.1.2（MIT），HTTP/TLS 使用现有 Axios 和 Node 网络栈。保留各依赖许可证，不对已有 GPL 二进制的发行义务作额外假设。

[RFC 9110 §15.3.7.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7.3) 要求拼接多个响应时使用相同的强验证器。候选版目前要求强 ETag，并对每个分块发送 If-Match、核对 206、Content-Range、总大小、编码和实际响应字节数。弱 ETag、忽略 Range、版本改变、权限错误明确停止，保留现场。源站不支持这些条件时，不通过猜测强行续传。

## 多线程和续传

- 默认 4 连接、4 MiB 分块，最多 16 连接、16 MiB 分块。每批请求有界，内存上限随连接数和分块大小确定。连接异常时减少后续并发，连续成功后逐步恢复。
- 同一块可自动经历多次中断并恢复；指数退避、抖动和 Retry-After 避免重试风暴。默认每块 15 分钟重试预算，耗尽后返回可恢复的 NETWORK_WAIT，而非删除文件。暂停会立即取消网络等待。
- 只有完整分块通过响应检查，才按指定偏移写入 `.biodl-part`。然后先同步数据，再追加并同步带 SHA256 校验链的 `.biodl-journal` 记录，最后更新已提交进度。
- 活跃进度来自已提交字节加当前正在接收的字节，从不读取稀疏文件逻辑长度作为完成量。重试会舍弃未完成分块的临时接收量，因此显示可以合理回退；不会伪造平滑递增或提前100%。
- 正常暂停等待写入结束，保存文件身份/大小/修改时间快照；文件未变化时可快速复用断点。异常退出或文件元数据变化时，逐块核对已提交数据，只使损坏块失效。不保证异常退出后无需读盘。
- 文件锁阻止同一目标被两个进程同时写入。强杀后需要等待陈旧锁到期（默认15秒），再重新运行同一命令。锁失效时停止写入。
- 所有块已提交且最后一次源版本核对通过后，以不覆盖目标的硬链接发布文件，再移除临时文件。最终文件和断点日志保留，后续运行可核对完成状态。普通预先存在的文件、Axel/Aria 断点一律不覆盖、不混用。

## 校验含义

分块 SHA256 在收到数据时计算，正常下载完成不额外整文件扫描 MD5。它能用于检测本地断点数据变化，不能证明源站内容本身正确。远端 ETag 也不是官方文件摘要；结果明确标记 `remoteChecksumVerified: false`。官方 MD5 仍应作为可选的独立全文检查，遇到不一致保留文件供核对，不以文件头尾或抽样代替全文保证。

本地文件系统和磁盘须正确实现同步写入；突然断电、控制器掉写、非协作外部程序修改文件等不能用软件宣称绝对可靠。本机强杀测试不等于物理断电测试。正常暂停的快速恢复针对本机常规文件系统；不对可伪造相同元数据的外部写入作保证。

## 使用和验证

```bash
npm ci
npm run test:native
npm run test:native:live
npm run native:download -- 'http://ftp.sra.ebi.ac.uk/vol1/fastq/SRR390/SRR390728/SRR390728_1.fastq.gz' -o /你的目录/SRR390728_1.fastq.gz --proxy http://127.0.0.1:43289
```

必须明确选择 `--proxy` 或 `--direct`；不会读取系统代理后悄悄降级直连。上述代理必须是已正常运行且获授权的本机加速通道。本程序不负责启动加速器、登录账号或扣流量。Ctrl+C 正常暂停；之后运行同一命令续传。CLI 输出结构化进度和错误码，不输出带凭据的URL或环境变量。

故障测试覆盖分段错误、五次连续断流、限流、超时、暂停、真实进程强杀、尾部日志撕裂、日志损坏、本地数据损坏、源版本变化、文件锁、磁盘/日志写入失败、代理不回退和旧文件保护。真实测试完整下载公开 EBI 文件并独立检查 ENA MD5，另下载 HTTPS 文件核对已知 SHA256。故障数据在临时目录中，结果在 `.evidence/native-*.json`。

## 正式接入前的范围

当前仅支持提供 Range 和强 ETag 的 HTTP(S) 静态文件，且目标文件系统需支持硬链接（APFS、常规 NTFS/ext4 等）；其他文件系统会保留完整临时文件并报错。FTP/SFTP、浏览器会话下载、没有强 ETag 的源、旧断点格式迁移仍用原引擎方案。

正式接入需要完成真实 Windows 长时间/多GB/多任务故障回归，测试不同磁盘和代理链路，再接入统一任务调度、账号计费、现有完整性检查、设置页与三端打包。保留旧引擎选择，不把已经存在的 `.st` 或 `.aria2` 解释为本内核断点。不因一次测试通过就宣称比成熟下载器在所有场景更优。
