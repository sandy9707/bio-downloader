# BioDownloader 专属内核（2.2.0-preview.1）

预览版新建 HTTP/HTTPS 任务默认使用专属内核。插件中心可直接选择 BioDownloader、aria2c 或 Axel，也可进入「按下载类型配置」。FTP/SFTP、FTPS、网页登录会话保留相应下载器。已有 `.st`、`.aria2` 或 `.biodl-journal` 断点固定使用原内核，不混合解释；升级不会把旧文件按新格式强行续传。

源站没有强 ETag、忽略 Range，或目标磁盘不支持安全发布时，仅在尚未创建文件及专属断点的情况下转用 aria2c，并显示原因。已经产生专属断点后不更换内核、不删除数据、不悄悄改为直连。

## 为什么续传能够接上

1. **固定位置**：默认每块 4 MiB。第一块负责字节 0–4194303，第二块负责 4194304–8388607。写入的是这些绝对位置，不是简单追加到文件末尾。
2. **同一个源文件**：先获取强 ETag 和完整大小，每个分段请求带 If-Match。严格核对 HTTP 206、Content-Range 起止位置、总大小、编码以及实际收到的长度。源版本改变就停止并保留断点。
3. **相邻块重叠检查**：每个内部边界额外请求前后各32字节。两块都返回同一段64字节，比较其 SHA256；不同则停止，不能发布为完成文件。临时文件只写本块负责的内容，重叠部分不重复写入。
4. **先数据后记录**：完整收到并检查一块后，计算分块 SHA256，写入 `.biodl-part` 并同步落盘，然后追加带校验链的 `.biodl-journal` 记录并同步，最后才记为已完成。
5. **恢复检查**：正常暂停或完整发布会保存文件身份、大小与修改时间快照。文件未变化时快速复用记录；强杀、断点日志尾部撕裂或文件元数据变化时核对已提交块的 SHA256，只补未确认/损坏块。日志中间损坏则保留现场，不猜测完成状态。
6. **完成条件**：所有块存在、范围覆盖完整、边界相符、文件大小一致、最终源版本检查通过，才以不覆盖现有目标的方式发布。单靠文件大小、进度100%或断点文件消失都不算完成。

重叠检查能发现边界错位或相邻响应不一致，不能证明源站内容本身正确；本地分块 SHA256 也不是官方摘要。若服务器错误地复用 ETag，且错误内容未落在重叠区域，仍可能无法发现。需要核对全文时使用可信的官方 MD5/SHA，MD5 保持可选，默认不再额外读取整文件。不能承诺任意网络、硬件掉写、物理断电或外部程序伪造相同文件元数据时绝对可靠。

## 运行与恢复策略

- 客户端每文件最多4连接，最多8个下载工作线程同时运行；其余等待。独立工作线程隔离下载、哈希与文件操作，正常暂停关闭当前网络及文件句柄，恢复仍属于同一个逻辑任务。
- 瞬时断流、429和5xx按块重试，退避并降低并发；默认每块15分钟重试预算，耗尽保留断点，网络恢复后可重试。暂停会中断等待。
- 进度使用实际接收字节，不读取稀疏文件逻辑长度冒充下载量。重试时未提交块的临时进度可以回退，只有完成检查和发布后才报告完成。
- 文件锁阻止两个进程同时写入。强杀后自动等待旧锁过期再尝试恢复。锁失效立即停止。
- 完成任务具有持久标识。上报流量使用服务端现有 dedupeKey 接口，成功后在断点日志保存账号摘要对应的确认记录，避免普通恢复重复上报。服务端现有去重窗口为1小时，不宣称跨任意时长异常中断的分布式计费绝对一次性。
- 预览引擎选择另存 `nativeDownloadEngines`，保留旧客户端能识别的 `downloadEngines`，方便回退。专属断点仍需要本预览版恢复；旧正式版不认识此断点格式。
- 目标目录需支持硬链接发布，开始前会探测。主要验证本机 APFS、NTFS、Linux 文件系统；网络共享盘及物理断电不在已验证保证内。

## 实现与验证入口

核心位于 `src/main/native-transfer`，客户端通过 `src/main/native-download.js` 调用独立 worker。参考 [aria2 分块存储](https://github.com/aria2/aria2/blob/master/src/DefaultPieceStorage.cc)、[调度](https://github.com/aria2/aria2/blob/master/src/DownloadEngine.cc)、[控制文件](https://aria2.github.io/manual/en/html/aria2c.html)、[Axel 多连接设计](https://github.com/axel-download-accelerator/axel) 和 [HTTP 范围响应标准](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7.3)，没有复制这些 GPL 项目的源码。网络使用现有 Axios/Node，文件锁使用 proper-lockfile（MIT），保留依赖许可证。

```bash
npm test
npm run test:desktop
npm run test:native:app -- --stress
npm run test:native:live
```

故障测试覆盖连续五次断流、限流、超时、暂停、真实强杀、本地损坏、日志撕裂、源变化、边界不一致、并发写锁、磁盘错误、代理不回退和旧文件保护。应用测试通过实际主进程IPC及worker执行超过2 GiB文件、三个并发任务、暂停/取消、主进程强杀恢复、独立全文SHA256及流量确认。真实 EBI 文件另外完整下载并独立比较 ENA MD5。测试输出位于 `.evidence/native-*.json`；CI及打包结果以实际成功记录为准。

独立CLI仍可用：

```bash
npm run native:download -- 'https://example.org/file' -o /你的目录/file --proxy http://127.0.0.1:43289
```

CLI必须明确选择 `--proxy` 或 `--direct`，不会启动加速器或处理账号计费。Ctrl+C暂停，再运行同一命令恢复。预览断点日志版本为2，未发布原型的版本1日志不自动迁移。
